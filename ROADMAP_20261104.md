## Phase 2: Multi-Tenancy & Team Collaboration [COMPLETED]

- **Workspaces & Organizations:**
  - Introduce an [`Organization`](file:///Users/hitesh/Learning/Code/headless-crm/src/main/java/com/example/headlesscrm/domain/Organization.java) entity with slug, name, and owner associations, enabling CRM data to belong to shared team workspaces rather than isolated single users. *(Completed)*
  - Auto-provision a default personal workspace upon user registration in [`AuthController`](file:///Users/hitesh/Learning/Code/headless-crm/src/main/java/com/example/headlesscrm/controller/AuthController.java) to ensure a frictionless onboarding experience. *(Completed)*
  - Implement full workspace management endpoints in [`WorkspaceController`](file:///Users/hitesh/Learning/Code/headless-crm/src/main/java/com/example/headlesscrm/controller/WorkspaceController.java) and [`WorkspaceServiceImpl`](file:///Users/hitesh/Learning/Code/headless-crm/src/main/java/com/example/headlesscrm/service/impl/WorkspaceServiceImpl.java) for creating, listing user workspaces, retrieving workspace details, updating metadata, and deleting workspaces. *(Completed)*
  - Re-scope [`Customer`](file:///Users/hitesh/Learning/Code/headless-crm/src/main/java/com/example/headlesscrm/domain/Customer.java) and nested [`Contact`](file:///Users/hitesh/Learning/Code/headless-crm/src/main/java/com/example/headlesscrm/domain/Contact.java) entities under organizations (`organization_id` foreign key) for multi-tenant data isolation. *(Completed)*
  - Implement dynamic workspace resolution via optional `X-Workspace-Id` HTTP header in [`CustomerController`](file:///Users/hitesh/Learning/Code/headless-crm/src/main/java/com/example/headlesscrm/controller/CustomerController.java) with graceful fallback to the user's primary/default workspace in [`WorkspaceServiceImpl`](file:///Users/hitesh/Learning/Code/headless-crm/src/main/java/com/example/headlesscrm/service/impl/WorkspaceServiceImpl.java), ensuring single-workspace API consumers continue operating seamlessly. *(Completed)*
- **Team Invitations & Membership Management:**
  - Model workspace invitations with email dispatch modeling and status lifecycle tracking (`PENDING`, `ACCEPTED`, `REJECTED`, `EXPIRED`) via [`OrganizationInvitation`](file:///Users/hitesh/Learning/Code/headless-crm/src/main/java/com/example/headlesscrm/domain/OrganizationInvitation.java) and [`InvitationStatus`](file:///Users/hitesh/Learning/Code/headless-crm/src/main/java/com/example/headlesscrm/domain/InvitationStatus.java). *(Completed)*
  - Provide complete invitation endpoints: invite members by email, list pending invitations, accept invitations, and decline invitations. *(Completed)*
  - Support direct team member management via [`OrganizationMember`](file:///Users/hitesh/Learning/Code/headless-crm/src/main/java/com/example/headlesscrm/domain/OrganizationMember.java): add existing registered users directly, list members, update member roles, and remove members / leave workspaces. *(Completed)*
- **Role-Based Access Control (RBAC):**
  - Implement a 4-tier granular role hierarchy via [`OrganizationRole`](file:///Users/hitesh/Learning/Code/headless-crm/src/main/java/com/example/headlesscrm/domain/OrganizationRole.java): `OWNER`, `ADMIN`, `MEMBER`, and `READ_ONLY`. *(Completed)*
  - Enforce access boundaries using centralized security verification in [`WorkspaceSecurityService`](file:///Users/hitesh/Learning/Code/headless-crm/src/main/java/com/example/headlesscrm/security/WorkspaceSecurityService.java):
    - `READ_ONLY`: View-only access to workspace resources; prohibited from mutating customer, contact, or member records. *(Completed)*
    - `MEMBER`: Full operational access to create and update customers and contacts; prohibited from deleting records or altering workspace membership. *(Completed)*
    - `ADMIN`: Team management authority, invitation management, and permission to perform soft-deletes on customers and contacts. *(Completed)*
    - `OWNER`: Full administrative and lifecycle authority, including member role adjustments and destructive workspace removal. *(Completed)*
  - Standardize `403 Forbidden` (`AccessDeniedException`) responses with RFC 7807 problem details in [`GlobalExceptionHandler`](file:///Users/hitesh/Learning/Code/headless-crm/src/main/java/com/example/headlesscrm/exception/GlobalExceptionHandler.java). *(Completed)*
- **Test Coverage & Regression Suite:**
  - Build comprehensive unit, service, and MockMvc controller test suites covering workspace scoping, membership transitions, invitation lifecycles, and RBAC authorization boundaries across [`WorkspaceControllerTest`](file:///Users/hitesh/Learning/Code/headless-crm/src/test/java/com/example/headlesscrm/controller/WorkspaceControllerTest.java), [`WorkspaceServiceImplTest`](file:///Users/hitesh/Learning/Code/headless-crm/src/test/java/com/example/headlesscrm/service/WorkspaceServiceImplTest.java), [`CustomerServiceImplTest`](file:///Users/hitesh/Learning/Code/headless-crm/src/test/java/com/example/headlesscrm/service/CustomerServiceImplTest.java), and [`ContactServiceImplTest`](file:///Users/hitesh/Learning/Code/headless-crm/src/test/java/com/example/headlesscrm/service/ContactServiceImplTest.java). *(Completed)*

## Phase 4: "Headless" Integration & Developer Ecosystem

- **API Key & Machine-to-Machine (M2M) Authentication:**
  - Allow users/admins to generate scoped API keys for server-to-server integrations, scripts, and headless frontends.
- **Outgoing Webhooks:**
  - Implement an event-driven mechanism (or Transactional Outbox pattern) to dispatch HTTP webhooks for key CRM events (e.g., `customer.created`, `deal.stage_updated`, `contact.deleted`).
- **Advanced Filtering & Search:**
  - Implement dynamic query specification (Spring Data JPA Specifications / QueryDSL) for filtering by tags, custom fields, and date ranges.
  - Enable full-text search across contacts and customers using PostgreSQL full-text search (`tsvector`) or search indexing.

## Phase 5: Production Hardening & Infrastructure

- **Database Migrations:**
  - Replace `hibernate.ddl-auto: update` in [`application.yaml`](file:///Users/hitesh/Learning/Code/headless-crm/src/main/resources/application.yaml) with **Flyway** or **Liquibase** for version-controlled, production-safe schema migrations.
- **Secrets Management:**
  - Externalize sensitive credentials (database password, JWT secret key) using environment variables and `.env` profiles.
- **Automated Testing Suite:**
  - Build comprehensive unit and integration tests using **JUnit 5**, **Mockito**, and **Testcontainers** for live PostgreSQL integration tests.
- **Containerization & CI/CD:**
  - Create a multi-stage `Dockerfile` and `docker-compose.yml` for local multi-container development (app + PostgreSQL).
  - Setup GitHub Actions CI workflow to run checkstyle, builds, and test suites automatically.
