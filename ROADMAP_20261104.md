# Headless CRM — Product Roadmap (2026-11-04)

This roadmap outlines key phases and development milestones to evolve this headless CRM repository from an initial MVP into an extensible, production-ready product.

---

## Phase 1: Complete Core CRUD & Robust API Design

- **Complete Entity Operations:**
  - Add missing endpoints to [`ContactController`](file:///Users/hitesh/Learning/Code/headless-crm/src/main/java/com/example/headlesscrm/controller/ContactController.java): get contact by ID, list all contacts for a customer, update contact, and delete contact.
  - Add missing customer endpoints to [`CustomerController`](file:///Users/hitesh/Learning/Code/headless-crm/src/main/java/com/example/headlesscrm/controller/CustomerController.java): get customer by ID, update customer details, and soft delete.
- **API Documentation & Contracts:**
  - Integrate **SpringDoc OpenAPI (Swagger UI)** to provide interactive API documentation, schemas, and contract testing.
- **Refined Error Handling:**
  - Replace generic `RuntimeException` throws across [`CustomerServiceImpl`](file:///Users/hitesh/Learning/Code/headless-crm/src/main/java/com/example/headlesscrm/service/impl/CustomerServiceImpl.java) and [`ContactServiceImpl`](file:///Users/hitesh/Learning/Code/headless-crm/src/main/java/com/example/headlesscrm/service/impl/ContactServiceImpl.java) with typed domain exceptions (e.g., `ResourceNotFoundException`, `DuplicateResourceException`).
  - Standardize error responses using RFC 7807 (Problem Details for HTTP APIs) via [`GlobalExceptionHandler`](file:///Users/hitesh/Learning/Code/headless-crm/src/main/java/com/example/headlesscrm/exception/GlobalExceptionHandler.java).

---

## Phase 2: Multi-Tenancy & Team Collaboration

- **Workspaces & Organizations:**
  - Introduce an `Organization` or `Workspace` entity so customers and contacts belong to a shared workspace rather than an isolated single user.
  - Implement workspace invitation and membership management.
- **Role-Based Access Control (RBAC):**
  - Expand beyond standard `ROLE_USER` to support granular team permissions (e.g., `WORKSPACE_ADMIN`, `SALES_REP`, `READ_ONLY`).
  - Secure service and controller methods using Spring Method Security (`@PreAuthorize`).

---

## Phase 3: CRM Domain Expansion

- **Deals & Pipelines:**
  - Model `Deal` entities with monetary value, close dates, stages (e.g., `Lead`, `Qualified`, `Proposal`, `Won`, `Lost`), and associations to customers/contacts.
  - Support configurable pipelines per organization/workspace.
- **Activity & Interaction Timeline:**
  - Create entities for logging calls, meetings, notes, and tasks linked to customers and contacts.
  - Provide an aggregate timeline endpoint to retrieve complete relationship history.
- **Custom Fields & Dynamic Metadata:**
  - Support arbitrary key-value or JSON attributes on CRM entities (using PostgreSQL `jsonb`) to allow headless consumers to customize data schemas without schema migrations.

---

## Phase 4: "Headless" Integration & Developer Ecosystem

- **API Key & Machine-to-Machine (M2M) Authentication:**
  - Allow users/admins to generate scoped API keys for server-to-server integrations, scripts, and headless frontends.
- **Outgoing Webhooks:**
  - Implement an event-driven mechanism (or Transactional Outbox pattern) to dispatch HTTP webhooks for key CRM events (e.g., `customer.created`, `deal.stage_updated`, `contact.deleted`).
- **Advanced Filtering & Search:**
  - Implement dynamic query specification (Spring Data JPA Specifications / QueryDSL) for filtering by tags, custom fields, and date ranges.
  - Enable full-text search across contacts and customers using PostgreSQL full-text search (`tsvector`) or search indexing.

---

## Phase 5: Production Hardening & Infrastructure

- **Database Migrations:**
  - Replace `hibernate.ddl-auto: update` in [`application.yaml`](file:///Users/hitesh/Learning/Code/headless-crm/src/main/resources/application.yaml) with **Flyway** or **Liquibase** for version-controlled, production-safe schema migrations.
- **Secrets Management:**
  - Externalize sensitive credentials (database password, JWT secret key) using environment variables and `.env` profiles.
- **Automated Testing Suite:**
  - Build comprehensive unit and integration tests using **JUnit 5**, **Mockito**, and **Testcontainers** for live PostgreSQL integration tests.
- **Containerization & CI/CD:**
  - Create a multi-stage `Dockerfile` and `docker-compose.yml` for local multi-container development (app + PostgreSQL).
  - Setup GitHub Actions CI workflow to run checkstyle, builds, and test suites automatically.
